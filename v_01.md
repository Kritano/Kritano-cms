## Task 01 — `@cms/types`

**What it is:** Shared TypeScript types used across all packages. No runtime code. Must be built first as every other package imports from it.

**Build:**

```
packages/types/
├── src/
│   ├── index.ts
│   ├── collection.ts     # Collection, Field, FieldType definitions
│   ├── document.ts       # Document, DocumentStatus types
│   ├── media.ts          # Media, MediaTransform types
│   ├── api.ts            # ApiResponse, PaginatedResponse, ApiError
│   ├── auth.ts           # User, Session, JwtPayload
│   ├── seo.ts            # SeoBlock type
│   └── config.ts         # CmsConfig, SiteConfig types
```

**Key types to define:**

```tsx
// Document status
type DocumentStatus = 'draft' | 'published'

// All field type names
type FieldType =
  | 'text' | 'textarea' | 'richText' | 'slug'
  | 'url' | 'number' | 'boolean' | 'datetime'
  | 'select' | 'multiSelect' | 'media' | 'relation'
  | 'seoBlock' | 'blocks' | 'array' | 'colour'

// Field definition shape
interface FieldDefinition {
  type: FieldType
  required?: boolean
  default?: unknown
  // ... type-specific options
}

// Collection definition shape
interface CollectionDefinition {
  name: string
  fields: Record<string, FieldDefinition>
}

// Paginated API response
interface PaginatedResponse<T> {
  data: T[]
  total: number
  page: number
  limit: number
  totalPages: number
}

// Standard API error
interface ApiError {
  code: string
  message: string
  field?: string
}

// SEO block (compound field)
interface SeoBlock {
  metaTitle:       string | null
  metaDescription: string | null
  ogTitle:         string | null
  ogDescription:   string | null
  ogImage:         string | null  // media URL
  noIndex:         boolean
}

// Block (flexible content)
interface Block {
  id:     string  // uuid
  type:   string
  fields: Record<string, unknown>
}
```

**Done when:** `bun run build` in `packages/types` produces clean output with no errors. All types exported from the index.

## Task 02 — `@cms/core` — Schema DSL

**What it is:** The schema definition layer. The `defineConfig`, `defineCollection`, and all field builder functions. No database yet — just the schema parsing and validation layer.

**Build:**

```
packages/core/src/
├── schema/
│   ├── defineConfig.ts       # Top-level config builder
│   ├── defineCollection.ts   # Collection builder
│   ├── fields/
│   │   ├── index.ts          # Exports all field builders
│   │   ├── text.ts
│   │   ├── textarea.ts
│   │   ├── richText.ts
│   │   ├── slug.ts
│   │   ├── url.ts
│   │   ├── number.ts
│   │   ├── boolean.ts
│   │   ├── datetime.ts
│   │   ├── select.ts
│   │   ├── multiSelect.ts
│   │   ├── media.ts
│   │   ├── relation.ts
│   │   ├── seoBlock.ts
│   │   ├── blocks.ts         # Flexible content blocks
│   │   ├── array.ts
│   │   └── colour.ts
│   └── validate.ts           # Schema validation on startup
```

**The DSL must support this exact config syntax:**

```tsx
import { defineConfig, defineCollection } from '@cms/core'

export default defineConfig({
  site: {
    name: 'My Site',
    domain: '<https://mysite.com>',
    language: 'en',
  },
  collections: [
    defineCollection('page', {
      fields: {
        title:         text().required(),
        slug:          slug().from('title'),
        body:          richText(),
        content:       blocks([
          block('hero', {
            heading:    text().required(),
            subheading: text(),
            image:      media(),
            ctaLabel:   text(),
            ctaUrl:     url(),
          }),
          block('text-block', {
            body: richText(),
          }),
          block('image-gallery', {
            images:  array(media()),
            caption: text().nullable(),
          }),
        ]),
        featuredImage: media(),
        status:        select(['draft', 'published']).default('draft'),
        seo:           seoBlock(),
      }
    }),
  ]
})
```

**Each field builder returns a chainable object:**

```tsx
text()                    // Basic text field
text().required()         // Mark required
text().min(3).max(100)    // Length constraints
text().nullable()         // Allow null
slug().from('title')      // Auto-generate from another field
select(['a','b']).default('a')
array(media())            // Array of another field type
blocks([block('hero', {...}), block('cta', {...})])
```

**Schema validation on startup:** When the CMS starts, it reads `cms.config.ts`, validates the schema (no duplicate collection names, no duplicate field names within a collection, relation targets exist, etc.), and throws a descriptive error if anything is wrong.

**Done when:** The DSL can be imported and used to define a config. `schema.validate()` passes on valid config and throws with a clear message on invalid config. Full unit test coverage on field builders and validation.

**✅ COMPLETED** — 2026-04-28. All 16 field builders implemented with chainable API. `defineConfig`, `defineCollection`, `block()` working. `validateSchema()` covers all error cases. 38 unit tests passing. `bun run build` clean.

## Task 03 — `@cms/core` — Database Layer

**What it is:** Drizzle ORM setup, auto-migration generation from schema, and the migration runner. PostgreSQL only.

**Build:**

```
packages/core/src/
├── db/
│   ├── client.ts             # Drizzle client, connection pool
│   ├── schema-generator.ts   # Converts CMS schema → Drizzle table definitions
│   ├── migration-generator.ts # Generates migration files from schema diff
│   └── migrations/           # Auto-generated migration files live here
```

**Schema → Drizzle mapping:**

| CMS field type | Postgres column type |
| --- | --- |
| text | varchar(255) |
| textarea | text |
| richText | jsonb (TipTap JSON) |
| slug | varchar(255) UNIQUE |
| url | varchar(2048) |
| number | numeric |
| boolean | boolean |
| datetime | timestamptz |
| select | varchar(100) |
| multiSelect | jsonb (string array) |
| media | uuid FK → media table |
| relation | uuid FK → target collection table |
| seoBlock | jsonb |
| blocks | jsonb (Block[] array) |
| array | jsonb |
| colour | varchar(20) |

**Every collection table automatically gets:**

- `id` — uuid, primary key, default gen_random_uuid()
- `status` — varchar(20), default ‘draft’
- `createdAt` — timestamptz, default now()
- `updatedAt` — timestamptz, updated on every write
- `publishedAt` — timestamptz, nullable

**Migration runner:**

```bash
cms migrate          # Apply all pending migrations
cms migrate:create   # Generate a new migration from current schema diff
```

On `cms migrate:create`:

1. Read current `cms.config.ts`
2. Compare against last applied migration state
3. Generate a new timestamped migration file with the SQL diff
4. Never modify existing migration files

**Done when:** Defining a collection in config, running `cms migrate:create`, then `cms migrate` creates the correct Postgres table. Adding a new field to the config and re-running creates an ALTER TABLE migration. Full integration tests against a real Postgres instance (use Docker in CI).

**✅ COMPLETED** — 2026-04-28. Schema generator maps all 16 field types to correct Postgres columns. Migration generator diffs snapshots and produces timestamped SQL files. Migration runner applies pending files in transactions. 78 tests passing (40 new for db layer). `bun run build` clean.

## Task 04 — `@cms/core` — API Server

**What it is:** The Hono API server. Auto-generates all REST routes and the GraphQL endpoint from the collection schema. Auth middleware. Media upload.

**Build:**

```
packages/core/src/
├── api/
│   ├── server.ts             # Hono app entry point
│   ├── router.ts             # Route registration
│   ├── middleware/
│   │   ├── auth.ts           # JWT verification middleware
│   │   ├── cors.ts           # CORS config
│   │   └── error.ts          # Global error handler
│   ├── routes/
│   │   ├── auth.ts           # /api/auth/*
│   │   ├── collection.ts     # /api/:collection/* (auto-generated)
│   │   ├── media.ts          # /api/media/*
│   │   ├── sitemap.ts        # /api/sitemap.xml
│   │   ├── health.ts         # /api/health
│   │   └── kritano.ts        # /api/kritano/* (webhook receiver)
│   └── graphql/
│       ├── schema-builder.ts  # Builds GraphQL schema from CMS schema
│       └── resolvers.ts       # Auto-generated resolvers
```

**REST routes (auto-generated per collection):**

```
GET    /api/:collection              List — paginated, filterable, sortable
GET    /api/:collection/:id          Single document by ID
GET    /api/:collection/slug/:slug   Single document by slug
POST   /api/:collection              Create document
PUT    /api/:collection/:id          Full update
PATCH  /api/:collection/:id          Partial update
DELETE /api/:collection/:id          Delete
POST   /api/:collection/:id/publish  Set status to published, set publishedAt
POST   /api/:collection/:id/unpublish Set status to draft, clear publishedAt
```

**List endpoint query params:**

- `?page=1&limit=20` — pagination
- `?status=published` — filter by status
- `?sort=publishedAt&order=desc` — sorting
- `?search=keyword` — basic title search (ILIKE for v0.1)

**Auth:**

- Write endpoints (POST, PUT, PATCH, DELETE, publish) require valid JWT
- Read endpoints for published documents are public (no auth)
- Read endpoints for draft documents require auth
- `POST /api/auth/login` — email + password → returns JWT + refresh token
- `POST /api/auth/refresh` — refresh token → new JWT
- `POST /api/auth/logout` — invalidate refresh token
- `GET /api/auth/me` — return current user

**Media:**

- `POST /api/media/upload` — multipart, accepts image files
- Sharp pipeline: auto-convert to WebP on upload, store original + WebP
- Generate thumbnail (400px wide) on upload
- Store: filename, original filename, mime type, size, width, height, alt text
- `GET /api/media` — list all media, paginated
- `PATCH /api/media/:id` — update alt text
- `DELETE /api/media/:id` — delete file and record

**Sitemap:** Queries all published documents across all collections, generates valid XML sitemap. Regenerates on every publish/unpublish.

**Health check:** `GET /api/health` returns `{ ok: true, version: '0.1.0' }`. Used by deployment scripts.

**Done when:** All routes respond correctly. Auth middleware blocks unauthenticated write attempts with 401. List pagination works. Media upload stores file and returns correct response. GraphQL endpoint returns correct data for a simple query. Full integration tests.

**✅ COMPLETED** — 2026-04-28. Hono server with all REST routes auto-generated from schema, JWT auth middleware, Sharp media pipeline, GraphQL Yoga endpoint, sitemap, Kritano webhook, health check. Auth blocks all write endpoints with 401. 94 tests passing (16 new API tests). `bun run build` clean.

## Task 10 — `@cms/sdk`

**What it is:** The typed API client. Used by the default Astro theme and any external frontend to consume the CMS API.

**Build:**

```

├── client.ts             # CMSClient class

└── types.ts              # Re-exports from @cms/types
```

**API:**

```tsx
import { CMSClient } from '@cms/sdk'

const cms = new CMSClient({
  url: '<https://mycms.com/api>',
  apiKey: process.env.CMS_API_KEY,  // Optional for public reads
})

// Collection queries — fully typed from schema
const articles = await cms.collection('article').findMany({
  where: { status: 'published' },
  orderBy: { publishedAt: 'desc' },
  limit: 10,
  page: 1,
})
// Returns: PaginatedResponse<Article>

const article = await cms.collection('article').findOne({
  where: { slug: 'my-article' }
})
// Returns: Article | null

// Media
const media = await cms.media.list({ limit: 20 })
```

**Type generation:** The SDK should generate collection-specific types from the schema at build time via `cms generate`. This makes `cms.collection('article')` return a client typed to the Article shape, not a generic `Record<string, unknown>`.
