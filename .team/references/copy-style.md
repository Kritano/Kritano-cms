# Copy Style References

## Tone
- Direct, confident, no fluff
- Developer-friendly but accessible to non-technical users
- No marketing speak in docs — show, don't tell
- British English spelling (colour, organisation, etc. — per blueprint)

## Documentation Style
- Every page has a working code example
- No page assumes knowledge from an unseen page
- Accurate against actual implementation — no aspirational features documented as real
- v0.2+ features marked clearly as "coming soon" if mentioned at all

## Error Messages
- Descriptive — tell the user what went wrong and how to fix it
- Schema validation errors should name the exact field and collection

## UI Copy
- Minimal labels, clear actions
- Button text should be verbs: "Publish", "Upload", "Save", not "OK" or "Submit"
